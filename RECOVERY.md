# Проверка доставки и восстановления

Проверено 29 октября 2026 года на отдельных контейнерах с пустой БД. Основная БД проекта не изменялась.

## Автоматические проверки

```sh
go test -race -v ./internal/scrapper/client/kafka -run TestRecoveryRealDatabaseAndKafkaRestart -count=1
go test -race -v ./cmd/agent -run TestAgentProcessRestartDrainsQueuedUpdates -count=1
go test -race -v ./internal/infrastructure/kafka -run TestConsumerDiscoversTopicCreatedAfterStartup -count=1
```

1. PostgreSQL останавливается: запросы завершаются ошибкой. После запуска прежний пул восстанавливает соединения, подписка, теги и Outbox сохраняются.
2. Kafka останавливается: публикация завершается ошибкой, статус Outbox остаётся PENDING. После запуска того же брокера прежний processor публикует исходное событие с автором и получателями, статус меняется на PROCESSED.
3. Настоящий процесс Agent завершается. Сообщение публикуется в Kafka во время его простоя. Новый процесс с прежней consumer group обрабатывает очередь и публикует результат с ожидаемым приоритетом.
4. Consumer запускается до создания топика. После создания топика сообщение обрабатывается без ручного перезапуска. Для этого включены WatchPartitionChanges и PartitionWatchInterval.

Тестовые контейнеры используют закреплённые на время теста порты: случайная смена порта после Stop/Start не должна подменять проверку восстановления клиента проверкой изменения адреса.

## Живой пользовательский сценарий

В личном чате с LinkTRackerrrrBot выполнены регистрация, добавление ссылки и тега, удаление и повторное добавление ссылки, просмотр списка.

- LT-LIVE-01: контролируемое событие в Outbox прошло Kafka → Agent → Bot → Telegram. Пользователь подтвердил получение один раз.
- LT-LIVE-02: Kafka и Agent остановлены, событие сохранено в Outbox со статусом PENDING. После запуска сервисов оно доставлено, отставание обеих consumer groups стало нулевым. Пользователь подтвердил получение один раз.
- Реальный GitHub API: временная подписка golang/go, запуск планировщика, извлечение настоящего события с автором, запись Outbox, обработка агентом, доставка Telegram. Получение подтверждено пользователем; временная подписка удалена.

Токен GitHub из исходного .env отклонялся с 401 Bad credentials. Публичный источник успешно проверен без токена только в конфигурации тестового стенда. Для обычного запуска следует убрать невалидный GITHUB_TOKEN либо заменить его действующим; исходный .env во время проверки не изменялся.

Тестовый стенд после проверки остановлен, его отдельные данные сохранены. Тесты не доказывают exactly-once: архитектура использует at-least-once, при аварии между отправкой Telegram и commit Kafka возможен повтор.
