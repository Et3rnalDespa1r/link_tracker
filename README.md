# LinkTracker

**LinkTracker** – интеллектуальный агрегатор обновлений, состоящий из Telegram-бота и фонового скраппера. Система отслеживает изменения на веб-страницах (GitHub, StackOverflow) и оперативно информирует пользователя о них через асинхронную событийно-ориентированную архитектуру.

## Архитектура и технологии

Проект разделен на два независимых микросервиса, взаимодействующих через очередь сообщений:
* **Scraper:** Периодически опрашивает внешние API (GitHub/StackOverflow), выявляет обновления и гарантированно доставляет события в очередь.
* **Bot:** Принимает команды от пользователей в Telegram, управляет подписками и слушает очередь для отправки уведомлений.

**Ключевые реализованные паттерны (HW1):**
* **Асинхронная коммуникация:** Переход от синхронного HTTP к Apache Kafka (настраивается через конфигурацию: паттерн Стратегия).
* **Transactional Outbox:** Гарантированная доставка уведомлений из Scraper. Обновление сущности и запись события в таблицу `link_updates_outbox` происходят в единой транзакции PostgreSQL. Отдельная Relay-горутина (OutboxProcessor) отвечает за публикацию событий в брокер.
* **Schema Registry & Avro:** Сообщения строго типизированы. Сериализация и десериализация происходят по Avro-схеме, хранящейся в Schema Registry, что исключает рассинхрон форматов между сервисами.

### Обоснование настроек топика Kafka (link.updates)
Для работы системы был создан топик `link.updates` со следующими параметрами:
* **`replication-factor = 3`**: В `docker-compose` развернут отказоустойчивый кластер из 3-х брокеров. Фактор репликации 3 гарантирует сохранность данных при выходе из строя до двух брокеров одновременно.
* **`partitions = 3`**: Позволяет масштабировать обработку уведомлений. Это дает возможность запустить до 3-х экземпляров сервиса `Bot` в одной Consumer Group для параллельной обработки сообщений.

## Инструкция по запуску

### 1. Настройка окружения
В корне проекта должен лежать конфигурационный файл или файл `.env`.
Убедись, что добавлены необходимые переменные:
```env
APP_TELEGRAM_TOKEN=твой_токен_бота
USE_KAFKA=true
```
### 2. Запуск инфраструктуры (Kafka, PostgreSQL, Schema Registry)
Перед стартом сервисов необходимо поднять контейнеры:
```bash
docker-compose up -d
```

### 3. Запуск микросервисов
Запустите оба сервиса в разных окнах терминала:

Запуск Скраппера:

```Bash
go run cmd/scrapper/main.go
```
Запуск Бота:

```Bash
go run cmd/bot/main.go
```

### 4. Запуск автотестов
В проекте реализованы тесты с использованием Testcontainers для проверки интеграции Scraper → Kafka → Bot:
```bash
go test -v ./...
```

## Функционал Telegram-бота
Бот поддерживает автоматическую регистрацию команд в меню Telegram:

/start — Начало работы и регистрация пользователя.

/help — Вывод списка доступных команд.

/track — Начать отслеживание новой ссылки.

/untrack — Прекратить отслеживание ссылки.

/list — Показать все отслеживаемые ссылки.
